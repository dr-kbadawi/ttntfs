TT NTFS Native

NTFS read & write for macOS. No kernel extension.

Plug in a Windows disk and use it in Finder — read and write — without lowering your Mac’s security or rebooting. Built on Apple’s FSKit, so it runs in user space like a normal app. Free software, GPL-2.0.

Why it’s different

No kernel extension

Every other read/write NTFS driver for the Mac loads a kext, which means Reduced Security and a reboot. This one doesn’t.

Checked by Windows

Windows’ own chkdsk found no problems on a volume this driver wrote 626 files to, and every file read back byte-for-byte.

Symlinks that work both ways

Links you make on the Mac open on Windows. Junctions and links Windows made resolve on the Mac.

Honest about the journal

A disk Windows didn’t eject cleanly mounts read-only and tells you why. Replay is one click, per volume, and never automatic.

Install

  1. Open the DMG and drag TT NTFS Native to Applications.
  2. Open it and press Enable Extension. The app enables its own file system extension — the switch in System Settings does not work for third-party FSKit modules on macOS 26, and the app says so.
  3. Plug in an NTFS disk. It appears in Finder, read/write.

The app lives in the menu bar. It shows each NTFS volume, whether it mounted read/write, and — if it didn’t — the reason and what to do about it.

Read this before writing to a disk you care about

This driver has been checked by Windows, but that is one Windows build, one disk, one pass — it is not a warranty. Keep a backup of anything you cannot replace. Journal replay reproduces Windows on every real crash we have captured, and it stays off unless you turn it on for a volume, at your own risk.

How it’s built

The core is the Linux kernel’s NTFS driver (fs/ntfs, Linux 7.1), ported to run in user space inside an FSKit extension. The journal-replay engine, the FSKit layer, the app and the test suites are new work by TechTag GmbH. Everything is under the GPL-2.0, and every change is in the open on GitHub — including the bugs we found in ourselves and how we found them.

If you want the engineering detail — what was verified against Windows and how, what is inferred rather than measured, and what is still open — it is all in the repository’s docs/.
